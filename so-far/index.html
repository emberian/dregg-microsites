Initiative 11 · L3

So
far.

A Claude Code session writes its transcript one line at a time. Every hundred lines a receipt says what a policy automaton has seen: the state it is in, how often its acceptance condition has been met, whether anything has gone irrecoverably wrong, and the root of a Merkle mountain range over every line so far. A follower written in Lean checks each receipt against the previous one, in work that depends on the window, not on the session's length.

The policy.

Two clauses, as one deterministic Büchi automaton (the product of a safety monitor and a liveness automaton, prod_accepts_iff):

□

Safety. No Bash call runs a command the operator has forbidden: git stash, git add -A, pkill -f / -x, killall, kill -u. Wrappers such as sudo, bash -c and ssh host '…' are peeled. Once tripped, tripped for ever.

◇

Liveness. Every human prompt is eventually followed by assistant text. Accepting: no prompt waiting. Büchi: accepting infinitely often.

No finite prefix can say a liveness clause holds: whatever has happened, the assistant could fall silent for ever (respLive_is_liveness). So the verdict is three-valued. viol is final and means every infinite continuation is rejected (verdict_viol_sound, verdict_monotone). Otherwise it is unknown, and that is a real "?": both outcomes stay possible (unknown_is_genuine). What the receipts carry for the liveness clause instead is exact: the number of accepting positions so far, which is unbounded exactly when the infinite session is accepted (buchi_iff_count_unbounded), and the last accepting position, so the current wait is certified to be at most n − last events.

Cost, counted.

The largest session on this machine, 27,775 transcript lines (44.9 MB), replayed through the same producer and follower in 278 windows. Per window the follower spends 2·w hash calls on the entries (their digests and their leaves), one per carry, and one per peak to bag the root. The peaks grow as log n (3 at the start, 11 at the end); nothing else does.

Clock time per window is dominated by hashing and parsing the window's own bytes: median 21.8 ms per window, 153 ns per byte. By quarter of the session the median was 289, 157, 133 and 120 ns per byte; the middle quarters ran while other builds loaded the same laptop, which is noise, not growth. The orange line is what a verifier without the previous receipt pays at each window: everything so far, again.

Which leg is which.

1

Proved (Lean, axioms propext / choice / Quot.sound). window_sound: an accepted receipt states exactly the automaton's run over the committed window, its counters and the MMR range it occupies. windows_compose: a chain accepted from genesis tracks the whole log; for every infinite continuation the state and counter are the infinite run's; a viol is a bad prefix; any range answer against any log with the final root is the monitored log's, every position present, unless a named hash collision occurred. Falsifiers: a dropped position, a dropped violating position, swapped windows, a flag-DFA reading and a counter reading of acceptance.

2

Executed. The follower is lake exe stream-check: Lean compiled to native code, deciding by the very function the theorems are about. Its hash is a pure-Lean BLAKE3; the Rust producer computes the same roots independently and stops if they ever differ.

3

Not proved. That the classifier means what its prose says: it reads command text syntactically (no eval, variables or scripts). That BLAKE3 has no collisions. The Rust audit read (verify_range) corresponds to the Lean range check by documentation only.

What this does not claim.

✗

that the session satisfies the liveness clause · nothing finite can

✗

succinctness · the follower reads each window's lines. A follower that sees only receipts needs the window proved in a circuit; counted (about 9,100 Poseidon2 permutations per 100 median-sized entries), not built

✗

a checkpoint join · the follower starts at genesis; no theorem lets it adopt a stranger's receipt k

✗

first-order obligations · "every tool call gets its result" needs a register per open call; the alphabet here is four symbols

✗

a perfect shell reader · three rounds of adversarial audit by a second model (gpt-6-astra) closed every blocker and major finding; two minor classifier gaps remain on record (quoting inside substitutions, env -S and long sudo options)
