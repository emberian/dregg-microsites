A receipt for an absence: one hundred thousand public documents, a two-pattern scanner, and a signed sentence saying it rejected none of them. Each part has a specific job: a compiler with a semantic proof, two independent corpus scans, one record proved as a STARK, and an authenticated tuple that anyone can reproduce.

The sentence.

{"v":"absence-receipt-v1",
 "policy_blake3":"9ed0fa10…",     the policy source
 "table_blake3":"21d0cd70…",      the automaton it compiled to
 "corpus_mmr_root":"17d69bbf…",   100,000 documents, in order
 "corpus_pin":"681f94fc…",        crates.io-index commit
 "n":100000,
 "count":0}

The documents are the first 100,000 files of the public crates.io index at a pinned commit · 1.77 GB of package metadata. The policy forbids an AWS access-key id (AKIA and sixteen capitals or digits) and any PEM private-key header with an uppercase label. The Lean policy compiler produces a 129-state automaton, with a proof that it accepts exactly the byte strings containing neither pattern. This is a claim about those two pattern families; it says nothing about other formats, encoded secrets, or credential validity.

Which leg is which.

1

Committed. The corpus is a Merkle mountain range over the documents' blake3 hashes. The 100,000 hashes are published, so anyone can recompute the root without downloading the index.

2

Compiled with a proof. policyc compiles the two alternatives, combines their certified tables, and checks a smaller reachable table before building the absence automaton. Every returned table carries its semantic proof in Lean. The native compilation took 28.86 seconds: 129 states and 33,024 transitions.

3

Re-executed. The count comes from a Lean program, compiled to native code, that folds the automaton over every byte of every document: 1.77 billion steps in 33.91 seconds on the shared Mac. Lean proves that this fold is the house DFA's acceptance, and that a count of zero means every document is accepted. A second run through the Rust runtime agrees: zero rejections, in 25.91 seconds.

4

One record proved. Lean emits a descriptor for one 2,048-byte document. It has 20 columns, 32 constraints, and 11 public inputs, including an eight-lane commitment to the ordered transitions and their length. The verifier recomputes that route from the supplied record and the policy table. The same proof and inputs refuse a different record; changed final state, route root, and length are refused too. This is one record's served-path evidence.

5

Signed. The body is signed with an ordinary SSH key (ssh-keygen -Y sign), and ssh-keygen -Y verify checks it. That authenticates the body under the demo key; it does not attest the checker binary, its execution, or where the scanned bytes came from. To check the claim itself, recompute the corpus root, re-run the table, and compare every field with the signed body.

What this does not claim.

✗

a proof about the corpus · the 100,000 verdicts are re-execution, and checking them means running them again

✗

that every surrounding tool is proved · JSON rendering, native code generation, command handling, and filesystem I/O remain outside the compiler's kernel statement

✗

zero secrets · the scanner looks for two byte patterns; nothing about other secret formats, encoded secrets, whether a match is a live credential, or confidentiality in general

✗

that the hashed documents are the first 100,000 of the pinned commit · re-running the selection against a clone checks that; nothing proves it

✗

an MMR inclusion proof inside the record STARK · its route binds the supplied word under the hash assumption, but the link from those bytes to the corpus's Blake3 leaf and root is checked externally by the replay

What it improved.

The first Rust compiler kept semantically identical derivatives in different shapes because its alternation normalizer omitted associativity. Repairing that made the original demo possible. The active pipeline now uses the proved Lean compiler. Repeated normalization was cached without changing the worklist result; the raw union became a certified product; 638 possible state pairs became 49 reachable pairs through a checked simulation. A cubic linked-list lookup in the factor construction was replaced by precomputed active targets, with a theorem that the result is exactly the old one.

Repeat the computation.

Clone the repository, then run one command. The first run builds the tools and fetches the pinned public corpus. It hashes and scans every document, re-emits the record descriptor, compares the complete computed tuple with the original signed receipt, and runs the one-record STARK test:

git clone https://github.com/emberian/dregg.git
cd dregg
demo/absence-receipt/run.sh replay

Requires Git, Rust, cargo-nextest, Python 3, OpenSSH with ssh-keygen -Y, and the pinned Lean toolchain. Set INDEX=/path/to/index to reuse the corpus. Outputs go to a fresh directory. The original receipt and trusted signer are preserved. For a quick signature and metadata check without scanning the corpus, use demo/absence-receipt/run.sh verify; that command explicitly reports that it has not rerun the computation.

Status, plainly: a demo, built in a day on public data. The pipeline, the hash list, the table, the receipt and its signature are in the dregg repository under demo/absence-receipt/, with the commands to reproduce every number.
